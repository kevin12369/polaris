# 给小公司的接入指南（10 分钟）

> 这份文档是给公司老板或 IT 负责人看的，不需要懂开发。

---

## 这是什么

一个装在你自己服务器上的技术支持工作台，用来管客户报障的问题。

四个功能：

1. **工单** —— 客户报障的问题统一进来，系统自动判断这是「登录问题」还是「接口报错」，自动定优先级，并且开始倒计时：P1 问题 4 小时内必须解决，超了会亮红灯。
2. **知识库** —— 每解决一个问题，点一下「沉淀为知识库」，把它存下来。下次同样的问题，AI 助手直接给出上次是怎么解的。
3. **AI 排障助手** —— 客服收到报错，粘进去，直接得到一份「先查什么、再查什么」的排查清单，不用每次都问技术。
4. **仪表盘** —— 一眼看到本月接了多少单、平均多久回复、超时多少单、有多少问题被沉淀成知识库。

---

## 需要什么

- 一台服务器：2 核 2G 就够，Docker 已装好（阿里云/腾讯云轻量应用服务器最便宜的那种就够）
- 一个域名（可选，没有就用 IP 访问）
- 10 分钟

**不用买任何服务。** 数据库就一个文件，跟着项目一起跑。

## 三步开通

### 第一步：拿到项目并启动

```bash
git clone https://github.com/kevin12369/support-workbench.git support-workbench
cd support-workbench
cp .env.example .env
```

改 `.env` 里的这一行，改成一个随机字符串（防止别人猜到登录令牌）：

```bash
python3 -c "import secrets;print(secrets.token_urlsafe(48))"
```

把生成的结果粘到 `.env` 的 `SECRET_KEY=` 后面。

然后启动：

```bash
docker compose up -d --build
```

### 第二步：开一个企业空间

浏览器打开 `http://你的服务器IP:8080`

点「免费开通」，填公司名、你的名字、邮箱、密码，**30 秒**就进系统了。

系统会自动给你一个独立的空间，这家公司的所有工单和知识库只有你们能看到。

### 第三步：加坐席、灌数据

- **加坐席**：让管理员在「退出登录」旁边……（如果需要我协助，直接告诉我同事的邮箱，我帮你加）
- **先跑一遍试试**：可以用演示账号 `demo@acme.com` / `demo1234` 看看效果，看完记得改掉或删掉这个账号

## 上线前请做这三件事

1. **改掉演示账号**（如果用了的话）
2. **确认 SECRET_KEY 已改成随机值**
3. **备份一次数据库**，把 `support.db` 存到你自己的网盘或对象存储

```bash
docker compose exec backend sh -c "cat /app/data/support.db" > backup-$(date +%F).db
```

## 日常怎么用

**客服的日常：**

1. 客户报障 → 在「工单」页点「＋ 新建工单」，把客户原话粘进描述
2. 系统自动标好分类和优先级，右侧开始倒计时
3. 处理过程中可以在详情页写备注，状态点一下就流转
4. 解决完，点「沉淀为知识库」，把这次的解法存下来

**技术负责人的日常：**

1. 遇到陌生报错，先用「AI 排障助手」粘进去看看有没有现成解法
2. 每周看一次「仪表盘」，重点看两个数：
   - **超时率** —— 超时说明工单量超过了承接能力，要么加人，要么把常见问题做成自助文档
   - **知识库命中率** —— 如果偏低，说明很多问题解决完没沉淀，下次还要重来一遍

## 常见问题

**Q：能接微信/邮件自动建单吗？**
可以。系统提供 `POST /api/tickets` 接口，字段传 JSON 就行。微信客服、邮件转工单都能对接。需要的话我帮你接。

**Q：数据存在哪？会不会丢？**
在 Docker 卷 `sw-data` 里，是一个 SQLite 文件。容器删了重建也不丢。要彻底备份就复制这个文件。

**Q：能不能换数据库？**
能，SQLite 换成 PostgreSQL 改动不大。但 50 人以下的规模没必要，SQLite 更快也更省事。

**Q：几个人用合适？**
5 到 50 人没问题。真要上百人再考虑换 Postgres。

**Q：安全吗？**
密码用 PBKDF2 加盐哈希存储，登录用 JWT 令牌。数据在你自己服务器上，不经过第三方。（如果配置了大模型接口，只有排障文本会发给那个接口；不配就完全不出网。）
