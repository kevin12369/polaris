## 第 4 步要做的事

### 4.1 部署到公网（半天）

产品需要一个外部可访问的地址，小公司才能登录使用。

**最快路径**：租一台轻量应用服务器（阿里云/腾讯云 2核2G，约 ¥60-100/月），
把项目推上去：

```bash
# 1. 服务器上
git clone https://github.com/kevin12369/polaris.git && cd polaris
cp .env.example .env
# 改 SECRET_KEY
docker compose up -d --build

# 2. 开放安全组 8080 端口（或用 nginx 反代到 80/443 + 域名）
```

> 需要我协助的话：告诉我服务器 IP、SSH 方式，我把部署脚本写好一键执行。

**成本对比**（写给客户听的话）：
- 这套：¥60–100/月（服务器）+ ¥0（软件）
- 商业工单系统：¥300–2000/月（按坐席）
- 自建开发：2 人月 = ¥10 万+

### 4.2 开通试用空间（5 分钟 / 家）

```bash
cd polaris/backend
docker compose exec backend python -m app.onboard "易宇通科技" \
  --admin 张三 --email zhang@kingtrans.net --password '初始密码' \
  --industry 跨境物流软件
```

命令会直接打印出可以发给对方的账号信息。新空间自带 8 条通用排查清单，
不会出现「打开是空白页」这种劝退体验。

### 4.3 触达（每个目标 1 通电话 + 1 次演示）

按优先级：

| 顺序 | 公司 | 为什么先做这家 |
|---|---|---|
| **1** | 易宇通科技（宝安） | 痛点直接写在招聘 JD 里（"整理技术支持FAQ"），团队最小，决策最快 |
| **2** | 联朗科技（福田） | 连锁门店场景，工单需求最刚；他们周六上班，能顺带验证 SLA 可配置 |

**触达话术**：`docs/推广话术.md`，三个版本（微信/邮件/现场演示脚本）。

**开场 5 个问题**（现场演示必问，用来调整演示重点）：
1. 客户报障现在走哪儿？微信群还是邮件？
2. 问题记录在哪儿？有专门的地方吗？
3. 客服几个人？一个人管多少客户？
4. 上个月接多少单、平均多久回复，有统计过吗？
5. 周末上班吗？SLA 按什么时间算？

### 4.4 一周后看数（关键）

试用满一周，让对方打开仪表盘，一起看这四个数：

| 指标 | 健康区间 | 不健康说明什么 |
|---|---|---|
| 平均响应时长 | < 2 小时（工作时间口径） | 客服人手不够或工单分类不准 |
| 超时率 | < 10% | 要么人手不足，要么优先级定得太松 |
| 知识库命中率 | 逐周上升 | 不涨 = 大家没有养成沉淀习惯，要推动 |
| 工单量 | 稳定 | 突然飙升 = 有系统性问题，不是单点故障 |

**知识库命中率是唯一一个「团队能力」指标**，其他三个更多反映运营。
如果一周后它还是 0%，说明产品在技术上没问题，是团队习惯没建立 ——
这时候该推的是「每周五花 10 分钟复盘本周工单，把重复的沉淀掉」。

## 风险提示（说在前面）

1. **SQLite 不适合高并发**：50 人以下没问题，别超。上量需要换 Postgres。
2. **附件没做**：如果对方强烈需要传截图，需要加一版（工作量小，半天）。
3. **没有邮件/微信自动建单**：目前要手工录，或走 API对接。这个是落地时最常见的卡点，
   建议第一个客户的需求就是它。
4. **SLA 工作时间是硬编码的**：如果客户周六上班（联朗科技就是），
   第一次演示前我应该先把它做成可配置，否则演示时承诺的东西产品做不到。
5. **商业化路径未设计**：现在是免费试用。要收费需要先想清楚按什么收费
   （按坐席？按工单量？一次性授权？），这个建议等第一个客户愿意续用再谈。
