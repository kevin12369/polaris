# 部署指南

本文档面向运维与实施人员，介绍如何在一台服务器上部署 Polaris。

- [English](DEPLOYMENT.en.md)

---

## 环境要求

| 项目 | 要求 |
|---|---|
| 服务器 | 2 核 2G 起（阿里云/腾讯云轻量应用服务器即可） |
| Docker | 20.10+ 与 Docker Compose v2 |
| 磁盘 | 1G 起步（数据库随工单量增长） |
| 域名 | 可选，无域名时用 IP + 端口访问 |

无需额外数据库服务、消息队列或 AI 服务。

---

## 三步部署

### 第一步：拉取代码并配置

```bash
git clone https://github.com/kevin12369/polaris.git polaris
cd polaris
cp .env.example .env
```

生成一个随机密钥填入 `.env` 的 `SECRET_KEY`（用于签发登录令牌）：

```bash
python3 -c "import secrets;print(secrets.token_urlsafe(48))"
```

`.env` 可配置项：

```bash
WEB_PORT=8080              # Web 界面暴露端口
SECRET_KEY=<随机字符串>     # 必填，务必修改
TOKEN_TTL_HOURS=72         # 登录令牌有效期
CORS_ORIGINS=*             # 生产环境建议改为具体域名
LLM_BASE_URL=              # 可选，OpenAI 兼容接口地址
LLM_API_KEY=               # 可选
LLM_MODEL=gpt-4o-mini      # 可选
```

### 第二步：启动

```bash
docker compose up -d --build
```

启动后访问 `http://<服务器IP>:<WEB_PORT>`。后端健康检查：

```bash
curl http://127.0.0.1:8000/api/health
```

### 第三步：创建企业空间

浏览器打开首页，点「免费开通」，填写企业名称、姓名、邮箱、密码即可。

每个企业空间数据完全隔离。管理员登录后可通过界面添加坐席账号，
或调用接口：

```bash
curl -X POST http://<host>:8000/api/auth/members \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{"name":"坐席姓名","email":"agent@company.com","password":"初始密码","role":"agent"}'
```

### 灌入演示数据（可选）

```bash
cd backend
python -m app.seed --reset
```

演示账号 `demo@acme.com` / `demo1234`。**生产环境使用前请删除或修改该账号。**

## 运维

```bash
# 查看日志
docker compose logs -f backend

# 备份数据库
docker compose exec backend sh -c "cat /app/data/support.db" > backup-$(date +%F).db

# 恢复数据库
docker compose exec -T backend sh -c "cat > /app/data/support.db" < backup-2026-11-02.db

# 重启后端
docker compose restart backend

# 查看卷
docker volume ls | grep polaris-data
```

### 数据库迁移

SQLite 的 `CREATE TABLE` 不会给已有表加列。应用启动时会自动执行轻量迁移
补齐新增字段，日志中会打印 `[migrate] 已补齐字段: ...`。也可手动执行：

```bash
docker compose exec backend python -m app.migrations
```

### 从旧版本名升级（support-workbench → polaris）

项目改名时同步调整了 Docker 卷名。**若此前用旧名部署过，数据卷需要迁移一次**，
否则 `docker compose up` 会起一个空库：

```bash
# 卷全名格式为 <项目目录名>_<卷名>，先用 docker volume ls 确认实际名字
docker volume ls | grep -E "sw-data|polaris-data"

# 1. 备份旧卷
docker run --rm -v support-workbench_sw-data:/old -v $(pwd):/backup alpine \
  tar czf /backup/old-sw-data.tar.gz -C /old .

# 2. 复制到新卷
docker compose up -d backend          # 先起一次以创建新卷
docker run --rm -v support-workbench_sw-data:/old -v polaris_polaris-data:/new alpine \
  sh -c "cp -a /old/. /new/"

# 3. 重启后端
docker compose restart backend
```

> 卷名取决于项目目录名。若 clone 时用了其他目录名，请按第 0 步的实际结果替换。

## 反向代理与 HTTPS

以 Nginx 为例：

```nginx
server {
    listen 443 ssl http2;
    server_name polaris.example.com;

    ssl_certificate     /etc/letsencrypt/live/polaris.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/polaris.example.com/privkey.pem;

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

前端容器自带 Nginx，已内置 `/api/` 反向代理规则，直接对外暴露 `WEB_PORT` 即可。

## 常见问题

**数据存在哪？会不会丢？**
在 Docker 卷 `polaris-data` 中，是一个 SQLite 文件。容器删除重建不丢数据。
彻底备份即复制该文件。

**可以换成 PostgreSQL 吗？**
可以，改动不大。但 50 人以下规模没有必要，SQLite 更省事也更快。

**适合多少人使用？**
5–50 人没问题。超过百人建议迁移到 PostgreSQL。

**安全机制？**
密码使用 PBKDF2-HMAC-SHA256（120k 轮）加盐哈希，登录使用 JWT 令牌，
密钥从环境变量注入。若配置了大模型接口，仅排障文本会发送至该接口；
未配置则完全不出网。

**如何接入微信 / 邮件自动建单？**
调用 `POST /api/tickets` 接口，提交 JSON 即可，字段见 `docs/API.md`。
